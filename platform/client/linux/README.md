# platform/client/linux

The Linux client backend: `openClient` in [backend.zig](backend.zig) returns the platform
interface's `ClientBackend`. Like the Windows backends, the OS APIs are called from small C
files behind a narrow header ([mlc.h](mlc.h)) that translate-c reads; Zig never sees the
system headers.

| Object | How |
| --- | --- |
| `Decoder` | libavcodec ([mlc_decode.c](mlc_decode.c)). VAAPI through `av_hwdevice_ctx_create` when a render node opens and has a VLD entrypoint for the codec, software otherwise. Low delay: `AV_CODEC_FLAG_LOW_DELAY`, slice threads only, so a picture comes out of the call that fed its access unit (tested). H.264, HEVC, and AV1 when libavcodec has it. The passthrough codec goes to the synthetic decoder, so this client plays against the synthetic host. |
| `Presenter` | Wayland `xdg_toplevel` with an EGL window surface and GLES 3 ([mlc_window.c](mlc_window.c)). VAAPI surfaces are exported as DRM PRIME and imported as two dma-buf EGLImages (R8 luma, GR88 chroma) with no copy; software NV12/I420 planes are uploaded as R8/RG8 textures; a shader converts BT.601/709, limited or full range. Lowest latency: swap interval 0 and the tearing-control `async` hint where the compositor has it; smooth: swap interval 1. The latency overlay ([common/overlay.zig](../common/overlay.zig)) is drawn on top. |
| `AudioSink` | A PipeWire playback stream, f32 ([mlc_audio.c](mlc_audio.c)), asking for a 256-frame quantum; the app writes into a 200 ms ring, the process callback copies one quantum out per cycle. `queued` is the ring plus the graph's reported delay. |
| `InputSource` | Keyboard and mouse from evdev ([evdev.zig](evdev.zig)): KEY_* to HID usages, buttons 1-5, motion per SYN_REPORT, high-resolution wheels at 120 per notch, CLOCK_MONOTONIC timestamps. Events count only while the window has keyboard focus (a seat with no keyboard, as in headless Weston, counts as focused); held keys are released when focus goes. Devices are rescanned every second. The window's close is `.quit`. Optional `grab` (EVIOCGRAB while focused). Gamepads come from platform/client/gamepad. |

The clock is `CLOCK_MONOTONIC`. Reading evdev needs the `input` group (the backend logs it
when it has no access). Wayland only: there is no X11 path.

## Build and test

Ubuntu 24.04 packages: `libavcodec-dev libavutil-dev libva-dev libwayland-dev libegl-dev
libgles-dev libpipewire-0.3-dev`; to run the tests headless also `weston libgl1-mesa-dri
pipewire wireplumber dbus-daemon`.

```sh
zig build test-linux                                   # skips what this machine lacks
platform/client/linux/headless.sh zig build test-linux # in a headless Weston + PipeWire
zig build moonsec-linux                                # moonsec-sim with --client linux
platform/client/linux/headless.sh zig-out/bin/moonsec-linux run sim --client linux --uinput-script
```

`--client linux` runs the client on this backend against the synthetic host. Every presented
picture is read back from the GL back buffer and its test-pattern stamp decoded, so the run
fails on a wrong or frozen picture after the real presenter. `--uinput-script` types the
host's key script on a uinput keyboard (needs write access to `/dev/uinput`) so the host's
injector check runs through the kernel and evdev.

CI ([.github/workflows/linux.yml](../../../.github/workflows/linux.yml)) runs all of this on
ubuntu-24.04 with Mesa llvmpipe. The runners have no GPU: the VAAPI path is built and its
fallback to software decode is tested, but hardware decode and the dma-buf import are
untested until there is a machine with a GPU.

## Files

- `mlc.h`: the Zig-facing C ABI. `mlc_internal.h`: error helpers for the C files.
- `protocol/`: xdg-shell and tearing-control-v1 client code, generated by wayland-scanner
  1.22 from wayland-protocols (`wayland-scanner client-header|private-code`).
- `uinput.zig`: a virtual keyboard and mouse for the tests and `--uinput-script`.
- `headless.sh`: runs a command in headless Weston with PipeWire and a null sink.
- `test.zig`: `zig build test-linux`; `MOONSEC_REQUIRE=wayland,pipewire,uinput` turns
  those skips into failures (CI sets it).
- `testdata/`: the Windows client's 128x96 H.264/HEVC test streams.
